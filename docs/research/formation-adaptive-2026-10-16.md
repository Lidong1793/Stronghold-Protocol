# 站位候选池与自适应演习（pool / adaptive，2026-10-16）

本页记录实验性站位模式 `pool` 与 `adaptive` 的设计和实测结果。两者都需要显式开启，即 `m.botFormationMode = 'pool' | 'adaptive'`，全局默认值不变。背景与历史实验见 [opus55-formation-handoff.md](opus55-formation-handoff.md)。

- 代码基线：master `0b467333`（0.3.0）。
- 固定条件：solo HARD/ABYSS、`band_ioleta`、experimental 采购、`preview,capacity`、`botRehearsal=3`。
- 漏怪按计入漏怪统计（含悬赏），窗口定义见 `tools/botbench/metrics.mjs`。

## 机制 [ASSUMED]

只改变最终站位的候选集合与演习名额。不改变评分、战斗规则、采购、阵容选择、召唤物或 Boss/隐藏关站位。

- **候选池**（`formationPoolSteps`）：
  - 顺序为 legacy:0 → learned → contact → refined → legacy:1–4；
  - 先去重，再按预算截断。修正了 combined 在去重前就截断、可能丢掉旧候选的问题；
  - legacy 变体按原来的顺序生成，所以 `m.rngBots` 的消耗与其他模式相同；示教规划不消耗随机数。
- **`pool`**：上述候选池，演习上限 `botRehearsal + 3`，与 combined 相同。
- **`adaptive`**：
  - 候选池之外，再加 3 种示教规划 × 4 个参数变体，去重后全部进入候选列表；
  - 演习按 `RehearsalRun` 的限制执行（`server/sim/rehearsal.js` `rehearsalLimits`）：前 `ADAPTIVE_STAGE = 3` 个候选一定演习；之后只有当已完成的最优候选仍有计入漏怪时才继续；累计 tick 超过 `ADAPTIVE_CAPS = 12` × 单候选上限后，不再开始新的候选；
  - 0 计入漏怪的候选已击杀全部计入敌人，后面的候选最多与它打平，而同分取先出现的候选。所以在 51–70 上，“0 漏怪即停止”与“全部演习”的决策逐项相同。
- **委托**：限制写进 `b.rehearsal` 帧（`stage`、`tickBudget`），主机的 Worker 使用同一个模块，在同一个候选处停止（见 `test/match/rehearsal-delegate.test.js`）。
- **诊断**：`m.botFormationTrace`，可用 `tools/botbench.mjs --trace F` 打开；不影响决策。

### 验收（对照 combined，留出集）

1. ABYSS 的 R1–10、R1–11 均不高于 combined，且逐种子好多于差：**通过**（7/1，16/1）。
2. HARD 的 R1–10、R1–11 不高于 combined 与 learned 中较好的那个：**通过**（15/22，持平）。
3. 配对 R12–13 不超过 +5%，Boss 到达数不下降：**通过**（ABYSS −11.5%，HARD −0.5%）。
4. 引擎错误 0；golden 288 个场景全部匹配：**通过**。
5. 准备耗时见下一节。

前 10 与前 11 回合两个窗口同时改善，没有取舍。

## 联机对照（coop4，种子 291–320）

条件：
- 每难度 30 局；跳过联防（`tools/botbench.mjs --no-unite`，只是加速实验，**不是**游戏规则）；
- 势力由 bot 自己选，队内不重复，所以只有拿到罗素的那一个座位使用实验采购；站位模式对所有座位生效；
- 漏怪为 4 个座位合计；7 组共 420 局，引擎错误 0。

| 策略 | HARD R1–10 / R1–11 | HARD 到达 Boss / 胜 | ABYSS R1–10 / R1–11 | ABYSS 到达 Boss |
|---|---|---|---|---|
| 原采购 + legacy | 1382 / 2028 | 24 / 7 | 3392 / 3949 | 6 |
| 原采购 + learned（游戏默认） | 1240 / 1895 | 27 / 13 | 3249 / 3728 | 8 |
| 原采购 + adaptive | 951 / 1539 | 29 / 11 | 2903 / 3479 | 6 |
| 实验采购 + learned | 1180 / 1740 | 28 / 9 | 3091 / 3507 | 12 |
| 实验采购 + combined | 1137 / 1694 | 26 / 8 | 3036 / 3556 | 9 |
| 实验采购 + pool | 1126 / 1671 | 27 / 11 | 3063 / 3585 | 11 |
| **实验采购 + adaptive** | **952 / 1478** | **29** / 10 | **2902 / 3436** | **15** |

- 实验采购 + adaptive 在两个难度的 R1–10、R1–11 都是最低或并列最低，ABYSS 到达 Boss 的局数也最多。
- 早期改善主要来自站位：只把站位换成 adaptive、采购不变，早期漏怪已接近同一水平。
- HARD 胜局以游戏默认最多（13 对 10）。30 局样本下，这个差距在噪声范围内。
- R12–13 受存活偏差影响（存活越久的组，后期回合计入越多），因此不列入比较。

## 局限与后续

- 单人只测了 band_ioleta 与 experimental 采购；联机只测了 coop4，且跳过联防。
- adaptive 每次最终站位要生成约 20 个启发式规划，启发式耗时大约翻倍。可以改为只在第一阶段仍漏怪时再生成后段候选。
- R12–13 演习与实战的偏差尚未定位。
- 是否把默认值或 `optimized` 切换到 adaptive，属于单独的产品决策。

## 补充：演习上限 3 次的约束（trio 与提前停止）

约束：不增加服务器演习负担。每次准备最多演习 3 个候选，与默认 AI（`legacy`，`botRehearsal=3`）相同。

### 机制 [ASSUMED]

- **`trio`**：按 `TRIO_SOURCES` 的优先级，取前 `m.botRehearsal` 个不重复的候选。前面已得到足够候选时，后面的不再规划。
- **提前停止**：`stage: 1`。任何一个已完成演习的候选为 0 计入漏怪，就不再演习后面的候选。
- 工具可用 `--trio` 覆盖优先级。

### 选择与验证

- **离线预选**（51–110，同一局面下的演习漏怪）：最好的三元组是 refined:2 + legacy:1 + learned:3，ABYSS R1–10/R1–11 为 80/204，而 legacy 前 3 个为 104/259。
- **实战筛选**（51–170）：learned → refined:2 → legacy:1 最好，HARD 23/43、ABYSS 225/519；legacy 为 44/72、284/588。
- **新种子验证**（171–290，此前从未使用；每难度 120 局，引擎错误 0）：

| 组 | 演习上限 | 平均演习数 HARD/ABYSS（51–70 测得） | HARD R1–10/R1–11 | ABYSS R1–10/R1–11 | 配对 R12–13 vs legacy |
|---|---:|---|---|---|---|
| legacy（默认 AI） | 3 | 2.98 / 2.98 | 39 / 71 | 244 / 515 | – |
| learned（当前游戏默认） | 4 | 3.97 / 3.97 | 36 / 63 | 203 / 472 | −3.2% / −6.1% |
| trio（learned, refined:2, legacy:1） | 3 | 1.07 / 1.38 | 34 / 47 | 239 / **548** | −0.5% / −1.0% |
| learned + 提前停止，上限 3 | 3 | 1.07 / 1.40 | 36 / 69 | 215 / 510 | +6.9% / −3.3% |
| learned + 提前停止，上限 4 | 4 | 1.09 / 1.56 | 36 / 64 | 203 / 472 | −3.5% / −6.1% |
| combined | 6 | – | 33 / 56 | 193 / 443 | −12.7% / −11.9% |

### 结论

- **`trio` 未通过验证**：ABYSS 的 R1–11 比 legacy 更差。筛选集上的优势主要来自选择偏差，不作推荐。
- **提前停止几乎无损**：learned 加提前停止后，240 局中有 233 局与 learned 逐回合完全相同，其余为极小差异；平均演习数从 3.97 降到 1.1–1.6，演习 tick 约为默认 AI 的 37–56%。
- **严格上限 3 时，只能小幅改善**：learned 上限 3 加提前停止，比 legacy 有改善，但比上限 4 明显差。HARD 的 R12–13 还高于 legacy +5%。
- 在“最多 3 次”的约束下，本轮没有找到稳定优于 learned（4 次）的方案。
